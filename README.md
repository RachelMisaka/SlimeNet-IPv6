# Detail：SlimeNet-IPv6实现文档

御坂瑞秋 2026/08/29

> **实现声明**：SlimeNet 拓扑本身与底层协议无关，本文所述 SlimeNet-IPv6 是其在 IPv6 上的一个特定实现，旨在最大化与现有以太网、WiFi、TCP/IP 等基础设施的兼容性，便于在现有环境下直接落地部署。
> 技术白皮书《readme.md》给出设计原理，本目录给出工程实现。各文档按依赖顺序阅读：《底层实现》是基础，其余文档在其上展开。

## 1. 文档结构

`底层实现.md` 描述网络的基础形态：新设备加入流程、路由系统、双路由表、同级边界、对上级层级的打包、路由卸载与无线容忍。`安全层实现.md` 在其上实现信任：角色判定、两阶段验证、信任状态与连通性、个人 GPG 认证、无 CA 组织的信任锚形态。`分布式时钟实现.md` 描述时钟这一基础机制：子网内时钟同步、跨子网校准、TAM 时间掩码，为安全层的时效判定供时。

`用户层实现.md` 描述整体的落地形态：一个用户态控制面守护进程（slimenetd）配合系统转发。发现、拓扑、路由解算、信任、时钟全部在进程内，转发交给内核，信任过滤在落表处执行。`兼容层实现.md` 界定网络边缘的能力鸿沟：标准节点、末端设备、兼容层三档角色，兼容设备由入口节点代管。

## 2. 架构概览

网络按层组织，每层是独立广播域，最多 256 个 mesh 节点，末端设备不占名额。节点通过 UDP 广播发现邻居，建立链路状态库，解算安全路由后写入系统路由表；普通传输只在安全路由上转发，未验证节点可被看见但永不成路径。逐级汇总、单向下行，下级明细绝不上行。

信任分双轨：组织 CA 轨管控制面（路由认证），个人 GPG 轨管数据面（端到端加密）。证书绑定 IPv6 地址，两阶段验证决定节点是否进入安全路由表。时钟经加权平均去中心化收敛，以时间戳载荷搭在广播上，支撑证书时效与防重放。

边界作为可配置的两端点组件，一套代码覆盖双归属与点对点两种形态，并行配置实现灾备与负载均衡。连通分量被切断时分裂为独立个体，重建连通时自愿融合，网络缩而不崩。

按《底层实现》1 → 2 → 《安全层实现》→《分布式时钟实现》的顺序先读控制面与信任，再读《用户层实现》看整体落地，最后读《兼容层实现》看边缘接入。想复现实验，参考《用户层实现》第 8 节的阶段验证路线。
